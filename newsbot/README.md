# Новостной фильтр Telegram-каналов

Читает заданные каналы, отбирает посты по реакциям и присылает отобранное вам в личку.

Два способа фильтрации, их можно комбинировать:

1. **По порядку реакций** — какая эмодзи на первом месте, какая на втором.
   Например: брать пост, только если первый смайл 👍, а второй 🔥.
2. **По количеству** — абсолютный порог, адаптивный порог «выше медианы канала»
   или доля реакций от просмотров.

---

## Почему нужен не только бот, но и аккаунт

Обычный бот **не может** читать чужие каналы: Bot API отдаёт посты только там,
где бот назначен администратором. Реакции он тоже не видит.

Поэтому здесь две части:

| Часть | Кто | Что делает |
|-------|-----|-----------|
| Читатель | ваш аккаунт Telegram (MTProto/Telethon) | заходит в каналы, видит посты, реакции, просмотры |
| Доставщик | обычный бот от @BotFather | присылает вам отфильтрованное |

Аккаунт-читатель должен быть **подписан** на каналы (для публичных достаточно,
чтобы канал был открытым). Он ничего не публикует и не ставит реакции — только читает.

> Заведите для читателя отдельный аккаунт на отдельной SIM. Файл сессии
> `newsbot.session` равнозначен доступу к аккаунту — его нельзя коммитить и
> пересылать. В `.gitignore` он уже закрыт.

## Установка

```bash
cd newsbot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 1. Ключи

`https://my.telegram.org` → API development tools → создать приложение.
Оттуда `api_id` и `api_hash`. Токен бота — у `@BotFather`.

```bash
cp .env.example .env
nano .env          # TG_API_ID, TG_API_HASH, BOT_TOKEN
```

### 2. Вход аккаунта-читателя (один раз)

```bash
python login.py
```

Скрипт спросит телефон, код из Telegram и пароль 2FA, создаст `newsbot.session`
и покажет ваш `user_id` — впишите его в `owner_ids`, чтобы ботом не мог
пользоваться посторонний.

Подсказка по каналам: `python login.py --list` выведет все каналы, на которые
подписан аккаунт, уже готовым куском YAML — можно вставить в конфиг.

### 3. Настройка

```bash
cp config.example.yaml config.yaml
nano config.yaml
```

### 4. Проверка порогов без отправки

```bash
python main.py --dry-run
```

Покажет в консоли, что прошло бы фильтр за последние сутки, и по какой причине.
Ничего не отправляет и очередь не засоряет — гоняйте, пока подбираете настройки.

### 5. Запуск

```bash
python main.py
```

Напишите боту `/start` — включится рассылка.

## Фильтр по порядку реакций

Это то, что видно на посте снизу: реакции выстроены по убыванию количества.
Платная звезда ⭐ всегда закреплена первой и **в рейтинге не участвует** —
«первый смайл» считается сразу после неё, как вы это и видите глазами.

```yaml
- username: "OstashkoNews"
  reaction_pattern:
    enabled: true
    patterns:
      - ["👍", "🔥"]      # первый 👍, второй 🔥
      - ["💯", "❤️"]      # или первый 💯, второй ❤️
  min_reactions: 0        # порог по количеству не нужен
  relative:
    enabled: false
```

Пост берётся, если совпал **хотя бы один** шаблон из списка.

Реальный пример — пост с реакциями `⭐ 👍113 🔥39 ❤️11 😢3` проходит,
а `⭐ 🤬1.6K 🙏542 ❤️198 🔥96` под шаблон `["🤬","😁"]` не проходит:
первый смайл тот, а второй — нет.

### Как писать шаблон

Все три записи эквивалентны:

```yaml
patterns:
  - ["👍", "🔥"]
  - "👍🔥"
  - "класс, огонь"
```

Понимаемые слова: `класс`, `дизлайк`, `огонь`, `сердце`, `100%`, `клоун`,
`злой`, `смех` (😁), `ржач` (🤣), `слеза`, `молитва`, `вау`, `думаю`,
`аплодисменты`, `молния`, `звезда` и другие — полный список в `reactions.py`.
Эмодзи всегда надёжнее слова.

Шаблон не ограничен двумя позициями — `["🤬", "😁", "🙏"]` проверит первые три.

### Режимы сопоставления

```yaml
reaction_pattern:
  match: prefix     # по умолчанию
```

| `match` | Что значит |
|---------|-----------|
| `prefix` | шаблон совпадает с **началом** рейтинга: 👍 первый, 🔥 второй |
| `anywhere` | эмодзи шаблона идут подряд в любом месте рейтинга |
| `top_set` | те же эмодзи в топе, порядок не важен |

### Совмещение с порогами

По умолчанию `gate: true` — шаблон обязателен: не совпал порядок, пост не берём.
Пороги при этом продолжают работать как дополнительное условие:

```yaml
reaction_pattern:
  patterns: [["👍", "🔥"]]
mode: all
min_reactions: 1000     # нужен и порядок 👍🔥, и минимум 1000 реакций
```

Если хотите «или шаблон, или много лайков» — поставьте `gate: false` и `mode: any`.

## Фильтр по количеству

```yaml
mode: any                 # any — хватит одного условия, all — нужны все

min_reactions: 1500       # абсолютный порог

relative:                 # адаптивный: «заметно выше обычного для канала»
  enabled: true
  factor: 2.0             # реакций ≥ медиана канала × 2
  min_samples: 20         # пока постов меньше — условие спит
  floor: 20               # ниже этого не пропускать никогда

min_engagement_rate: 0.02 # реакции / просмотры ≥ 2%
```

Адаптивный порог удобен, когда каналы разного размера: не придётся подбирать
число для каждого. Медиана считается по накопленной статистике, поэтому первые
пару дней после запуска работает только абсолютный порог.

Жёсткие отсечки работают всегда, независимо от `mode`: `min_views`,
`keywords_include`, `keywords_exclude`, `skip_forwards`.

## Доставка

```yaml
delivery:
  mode: instant                     # или digest
  digest_times: ["09:00", "19:00"]
  timezone: "Europe/Moscow"
  max_per_batch: 15
```

- `instant` — пост приходит, как только прошёл фильтр (с задержкой на «настаивание»).
- `digest` — копится и приходит пачкой в указанное время.

### Выдержка перед оценкой

Пост оценивается не сразу после публикации, а через `scan.min_age_minutes`
(по умолчанию **15 минут**): свежему посту реакции ещё не успели набраться, и
порядок смайлов в первые минуты скачет.

```yaml
scan:
  min_age_minutes: 15   # ждём 15 минут, потом смотрим на реакции
  interval_sec: 300     # обход каналов раз в 5 минут
```

Реально пост попадёт под проверку через 15–20 минут после публикации: сначала
истекает выдержка, потом до него доходит ближайший обход. Хотите точнее к 15
минутам — уменьшите `interval_sec` до 60.

Если пост с первого раза не прошёл, он переоценивается при каждом следующем
обходе, пока не выйдет за `scan.max_age_hours`. То есть пост, у которого нужный
порядок реакций сложился только к вечеру, всё равно придёт. А вот наоборот не
работает: пост, отправленный на 15-й минуте, повторно не проверяется — если
порядок смайлов потом поменялся, отзывать уже нечего. Чем короче выдержка, тем
чаще такое возможно.

## Команды бота

| Команда | Что делает |
|---------|-----------|
| `/start` | подписаться на рассылку |
| `/stop` | отписаться |
| `/status` | режим доставки, размер очереди, статистика |
| `/channels` | каналы, их шаблоны и пороги, накопленная медиана |
| `/digest` | прислать накопленное прямо сейчас |
| `/top 12` | топ постов за 12 часов, независимо от фильтра |

## Тесты

```bash
python test_filter.py
```

Прогоняет фильтр на реальных примерах постов: проверяет разбор шаблонов,
исключение платной звезды из рейтинга, совпадение и несовпадение порядка реакций,
все три режима `match` и совместную работу с порогами.

## Ограничения и осторожность

- **Telethon 1.44+ обязателен.** В версиях до 1.44 нет типа `ReactionPaid`, и
  платная звезда ⭐ ломает разбор списка реакций — а она есть почти во всех
  крупных каналах.
- Аккаунт-читатель работает через MTProto. Не уменьшайте `scan.interval_sec` и
  `pause_between_channels_sec` без нужды: частый опрос многих каналов повышает
  риск ограничений со стороны Telegram. При `FloodWait` бот сам ждёт нужное время.
- Ссылки на посты приватных каналов (`t.me/c/...`) откроются только у того, кто
  на канал подписан.
- Бот не пересылает медиа — присылает карточку с текстом и ссылку. Превью поста
  Telegram подтягивает сам.

## Структура

| Файл | Назначение |
|------|-----------|
| `main.py` | запуск, циклы сканирования и доставки |
| `collector.py` | чтение каналов и логика фильтра |
| `reactions.py` | нормализация эмодзи и разбор шаблонов |
| `config.py` | загрузка и валидация конфигурации |
| `storage.py` | SQLite: статистика постов, очередь, подписчики |
| `bot.py` | команды бота и рассылка |
| `formatter.py` | вёрстка карточки поста |
| `login.py` | разовая авторизация аккаунта-читателя |
| `test_filter.py` | тесты фильтра |
