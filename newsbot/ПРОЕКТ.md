# Новостной фильтр по реакциям — описание проекта

**Статус:** код готов и покрыт тестами, не развёрнут
**Репозиторий:** `proektzevaki-droid/25-tochek`, ветка `claude/telegram-news-bot-filter-swmhu7`, папка `newsbot/`
**Дата:** август 2026

---

## 1. Задача

Андрей читает несколько новостных Telegram-каналов. Каналы публикуют десятки
постов в день, из которых интересна малая часть. Читать всё подряд — трата
времени, отписаться — потерять нужное.

Нужен бот, который сам просматривает каналы, отбирает интересные посты и
присылает их одной лентой в личку.

**Ключевая идея отбора:** интересность поста определяется не количеством
реакций, а тем, **какие именно реакции стоят на первых местах**. Аудитория
канала своим выбором эмодзи размечает материал лучше любого анализа текста:
пост, на который люди ставят 👍 и 🔥 — это одно, пост с 🤬 и 😢 впереди —
совсем другое. Причём в разных каналах интересны разные типы.

---

## 2. Архитектурное ограничение, определившее решение

Обычный Telegram-бот **не может читать чужие каналы**. Bot API отдаёт посты
только там, где бот назначен администратором, а реакции не отдаёт вообще.
Добавить своего бота админом в чужой новостной канал невозможно.

Поэтому система состоит из двух частей:

| Часть | Что это | Что делает |
|-------|---------|-----------|
| **Читатель** | аккаунт Telegram, работает по протоколу MTProto (библиотека Telethon) | заходит в каналы как обычный пользователь, видит посты, реакции и просмотры |
| **Доставщик** | обычный бот от @BotFather | присылает отобранное в личку |

Читатель ничего не публикует и не ставит реакции — только читает. Аккаунт
должен быть подписан на отслеживаемые каналы.

> **Требование к версии:** Telethon **1.44 и выше**. В более ранних версиях нет
> типа `ReactionPaid`, и платная звёздная реакция ⭐ ломает разбор списка
> реакций. Звезда есть почти во всех крупных каналах, так что на 1.36 система
> просто не работала бы.

## 3. Как работает отбор

### 3.1. Рейтинг реакций

Под постом реакции выстроены по убыванию количества. Платная звезда ⭐ всегда
закреплена первой независимо от числа — её из рейтинга исключаем, потому что
для человека «первый смайл» это следующий за ней.

Пример поста:

```
⭐    👍 113    🔥 39    ❤️ 11    😢 3
     ↑ первая  ↑ вторая
```

Рейтинг для фильтра: `👍 🔥 ❤️ 😢`.

### 3.2. Выдержка перед оценкой

Пост оценивается **не сразу после публикации, а через 15 минут**. В первые
минуты реакции ещё набираются, и порядок смайлов скачет.

Каналы опрашиваются раз в 5 минут, поэтому реально пост проверяется через
15–20 минут после выхода.

Пост, не прошедший фильтр с первого раза, **переоценивается при каждом
следующем обходе в течение суток**. Если нужный порядок сложился только к
вечеру — пост всё равно придёт. Обратное не работает: отправленный пост
повторно не проверяется.

### 3.3. Язык шаблонов

Шаблон описывает требования к позициям рейтинга. В каждой позиции можно писать
не одну эмодзи:

| Запись | Значение |
|--------|----------|
| `"👍"` | ровно эта реакция |
| `"👍\|🔥\|💯"` | любая из перечисленных |
| `"!🤬\|😢"` | любая, **кроме** перечисленных |
| `"*"` | любая |

Позиции разделяются запятой. **Длина шаблона задаёт, сколько позиций
проверяется:** шаблон из одного элемента смотрит только на первую реакцию,
остальные не трогает.

Список `patterns` объединяется по «или»: пост проходит, если совпал хотя бы
один шаблон.

Реакции можно называть словами — `класс`, `огонь`, `злой`, `смех` — но эмодзи
надёжнее: в наборе Telegram есть похожие смайлы (😁 и 🤣), и слово может
разойтись с тем, что имелось в виду.

## 4. Правила по каналам

Правила выведены из размеченных примеров: Андрей присылал скриншоты постов с
пометкой «нужен» / «не нужен». Каждый пример зафиксирован в `test_filter.py` —
если правило изменят и оно сломает старый пример, тест это покажет.

### 4.1. Осташко! Важное (@OstashkoNews)

```yaml
patterns:
  - "!🤬|😢|😭|🙏|💩|🤮|💔|🕊|👎, !🤬|😢|😭"
```

**Смысл:** гнев и скорбь не должны попадать в первые две реакции. Отсекаются
посты про трагедии и потери, проходят те, где аудитория одобряет, смеётся или
недоумевает.

| Позиция | Запрещено |
|---------|-----------|
| Первая | 🤬 😢 😭 🙏 💩 🤮 💔 🕊 👎 |
| Вторая | 🤬 😢 😭 |
| Третья и дальше | без ограничений |

Списки для позиций **намеренно разные**: во второй позиции 👎 и 🙏 у нужных
постов встречаются регулярно, а 🤬 не годится нигде.

**Проверено на 36 постах:** 26 нужных проходят, 10 ненужных отсекаются.

Наблюдавшиеся сочетания у нужных постов:

- на первом месте: 👍 🔥 💯 😁 🤡 ❤️ 🤣
- на втором: 🔥 ❤️ 🤡 👏 👎 🤣 💯 👍 😁 🙏 🤔

Показательный случай: пост `🤡 723 / 🤬 262` — ненужный, хотя 🤡 впереди у
нужных постов встречается дважды. Именно он показал, что одной первой позиции
недостаточно.

**Не подтверждено примерами:** 🙏 и 👎 в первой позиции ни разу не встречались
ни среди нужных, ни среди ненужных — включены по смыслу. Также 😭 💩 🤮 💔 🕊
не встречались вообще.

### 4.2. Украина Online (@UaOnlii)

Здесь по решению Андрея сочетания записаны **буквально, без выведения общего
правила**. Список закрытый: чего в нём нет — то не нужно.

| Первая | Вторая |
|--------|--------|
| 🤬 | 😁 · 🙏 · 😢 · 🤯\|🥴 · 🔥 · ❤️ |
| 🙏 | 🤬 · ❤️ |
| 😢 | 😨\|😱 · 🙏 · 🤬 |
| 😁 | 🤬 |

Итого 12 сочетаний, собранных по 19 отмеченным постам. Два сочетания записаны
с альтернативой (`🤯|🥴`, `😨|😱`), потому что на скриншотах эмодзи не
различить, а подходят оба.

Новое сочетание добавляется одной строкой в `config.yaml`.

### 4.3. Каналы дают противоположные срезы

Один и тот же пост `🤬 2043 / 😢 140` в UaOnlii проходит, в Осташко — нет.
Пост `👍 523 / 😁 138` — наоборот. Из Осташко отбираются хорошие новости, из
UaOnlii — плохие. Настройки у каналов независимые, это зафиксировано отдельным
тестом.

## 5. Дополнительные фильтры

Помимо порядка реакций доступны (сейчас для обоих каналов выключены):

| Фильтр | Назначение |
|--------|-----------|
| `min_reactions` | абсолютный порог количества реакций |
| `relative` | адаптивный порог: «в N раз выше медианы канала». Удобен для каналов разного размера — не надо подбирать число вручную |
| `min_engagement_rate` | доля реакций от просмотров |
| `min_views` | минимум просмотров |
| `keywords_include` / `keywords_exclude` | по словам в тексте, например отсев рекламы по `erid` |
| `skip_forwards` | игнорировать репосты |

Режим `mode: any` — достаточно одного условия, `all` — нужны все.
Фильтр по порядку реакций при `gate: true` обязателен независимо от режима.

## 6. Архитектура

```
Каналы Telegram
      │  MTProto (аккаунт-читатель, Telethon)
      ▼
  collector.py ── разбор реакций, применение фильтра
      │
      ▼
  storage.py (SQLite) ── статистика постов, очередь, подписчики
      │
      ▼
  bot.py (aiogram) ── доставка в личку + команды
      │
      ▼
  Личка Андрея
```

Один процесс, три параллельные задачи: обход каналов, доставка, приём команд.

### Файлы

| Файл | Назначение |
|------|-----------|
| `main.py` | запуск, циклы сканирования, дайджеста и очистки |
| `collector.py` | чтение каналов, разбор реакций, логика фильтра |
| `reactions.py` | нормализация эмодзи, разбор шаблонов, сопоставление |
| `config.py` | загрузка и валидация конфигурации |
| `storage.py` | SQLite: статистика, очередь, подписчики |
| `bot.py` | команды бота и рассылка |
| `formatter.py` | вёрстка карточки поста |
| `login.py` | авторизация аккаунта-читателя, список каналов, `--whoami` |
| `test_filter.py` | тесты фильтра на всех размеченных примерах |
| `setup.sh` | мастер установки |
| `deploy.sh` | установка и обновление без вопросов |

### База данных

| Таблица | Назначение |
|---------|-----------|
| `posts` | метрики каждого просмотренного поста, флаги «прошёл фильтр» и «отправлен» |
| `subscribers` | кому слать |
| `meta` | служебные отметки, например когда последний раз ушёл дайджест |

Статистика старше 30 дней удаляется автоматически. Она же служит основой для
адаптивного порога.

## 7. Доставка

Два режима:

- **instant** — пост приходит, как только прошёл фильтр (с учётом выдержки);
- **digest** — копится и приходит пачкой в заданное время, например 09:00 и 19:00.

Сейчас настроен `instant`.

Карточка поста содержит название канала, количество реакций и просмотров,
разбивку по эмодзи, отрывок текста и ссылку на оригинал. Медиа не пересылается
— превью подтягивает сам Telegram по ссылке.

Между сообщениями выдерживается пауза, при упоре в лимиты Telegram бот ждёт
нужное время и продолжает.

### Команды бота

| Команда | Что делает |
|---------|-----------|
| `/start` | подписаться |
| `/stop` | отписаться |
| `/status` | режим доставки, размер очереди, статистика |
| `/channels` | каналы, их шаблоны, накопленная медиана |
| `/digest` | прислать накопленное сейчас |
| `/top 12` | топ постов за 12 часов независимо от фильтра |

Доступ ограничен списком `owner_ids` — посторонний, нашедший бота, получит
отказ.

## 8. Развёртывание

Сервер 77.73.232.184, отдельная папка `~/newsbot` со своим виртуальным
окружением и своим systemd-юнитом. С дашбордом 25 точек общий только сервер —
код, база и сервис независимы, перезапуск одного не задевает другой.

```bash
cd /home/devartemiy/25tochek/Dashborad
git fetch origin && git checkout claude/telegram-news-bot-filter-swmhu7 && git pull
cd newsbot && bash setup.sh
```

`setup.sh` ставит окружение, спрашивает ключи, логинит аккаунт, подставляет
`user_id` в `owner_ids`, прогоняет тесты и показывает, что прошло бы фильтр за
сутки. Повторный запуск безопасен: заполненные ключи и готовая сессия не
трогаются, обновляется только код.

Запуск после проверки:

```bash
sudo systemctl enable --now newsbot
sudo journalctl -u newsbot -f
```

## 9. Безопасность

Файл сессии `newsbot.session` равнозначен полному доступу к аккаунту-читателю.
Меры:

- папка `~/newsbot` с правами `700`, `.env` и файл сессии — `600`;
- `.env`, `*.session` и база закрыты в `.gitignore`, в репозиторий не попадают;
- токен бота при установке вводится скрыто, в историю терминала не пишется;
- команды бота принимаются только от `owner_ids`.

Решением Андрея читателем выступает его основной аккаунт. Компромисс осознан:
подписки на каналы уже есть, заводить отдельный аккаунт не потребовалось.

## 11. Известные ограничения

- **Порядок реакций может измениться после отправки.** Пост отправляется на
  15-й минуте и повторно не проверяется. Чем короче выдержка, тем чаще
  возможны такие случаи. При необходимости выдержка поднимается до 30–45 минут
  одной строкой в конфиге.
- **Не подтверждённые примерами позиции** в правиле Осташко (🙏 и 👎 первыми)
  — при первом же несовпадении правятся одной строкой.
- **Список UaOnlii закрытый:** сочетание, которого нет в списке, не придёт,
  даже если оно очевидно подходящее. Это осознанный выбор — правило не
  выводится, записывается буквально.
- **Ссылки на посты приватных каналов** (`t.me/c/...`) открываются только у
  подписчиков канала.
- **Частота опроса.** Уменьшать интервал обхода без нужды не стоит: частые
  запросы к многим каналам повышают риск ограничений со стороны Telegram. При
  `FloodWait` бот сам выжидает положенное время.
